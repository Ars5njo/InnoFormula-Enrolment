# InnoFormula · посещаемость клуба

[Открыть лидерборд](https://ars5njo.github.io/InnoFormula-Enrolment/) · [Проверки и публикация](https://github.com/Ars5njo/InnoFormula-Enrolment/actions)

Одностраничное Flutter Web приложение: общий рейтинг за всю историю клуба. Одна встреча даёт одно посещение, даже если участник записан несколько раз. Равные результаты получают места **1, 2, 2, 4**, внутри равного места идентификаторы сортируются по алфавиту. Рейтинг считается в браузере при загрузке страницы.

Если встреч нет, сайт показывает пустой рейтинг. Демонстрационные участники не включены в опубликованные ассеты.

## Разработка

Версия **Flutter 3.47.4 / Dart 3.13.3** зафиксирована в `.fvmrc`; CI читает её из этого же файла.

```sh
fvm install
fvm flutter pub get
fvm flutter run -d chrome
```

Если Flutter 3.47.4 уже установлен, команды можно запускать без `fvm`.

Подключите проверку посещаемости **до каждого коммита** один раз для своей копии:

```sh
git config core.hooksPath .githooks
```

Хук запрещает частично проиндексированные изменения посещаемости, чтобы проверять именно коммитируемые данные. В CI проверка повторяется независимо от локального хука.

## Добавить встречу

### 1. Подготовить список

Сохраните исходные почты по одной на строку **вне папки репозитория**, например в `../innoformula-private/emails.txt`. В ассетах должны находиться только готовые идентификаторы.

```sh
mkdir -p ../innoformula-private
# Сохраните исходный список в ../innoformula-private/emails.txt.
fvm dart run tool/attendance.dart prepare \
  --input ../innoformula-private/emails.txt \
  --registry ../innoformula-private/identities.json \
  --date 2026-09-15 \
  --name первая-встреча
```

Утилита проверяет почты, удаляет домены, обрезает пробелы, приводит регистр к нижнему, удаляет повторы и сортирует результат. Пустые строки игнорируются; поддерживаются LF, CRLF и CR. Пустой исходный список считается ошибкой. До завершения проверки файл встречи не изменяется. Диагностика не печатает исходные почты.

Результат: `assets/attendance/2026-09-15-первая-встреча.txt`:

```text
a.ivanov
e.smirnova
m.petrov
```

`identities.json` — локальный реестр соответствия идентификатора исходному адресу. Используйте **один и тот же реестр для всех встреч**, храните его вместе с исходными списками вне Git и сохраняйте резервную копию. Он позволяет обнаружить, например, один идентификатор с разными доменами в разных встречах. Утилита останавливается при таком совпадении; нужно выяснить, один ли это человек, и исправить исходные данные до публикации. Реестр не удаляет старые соответствия при исправлении встречи.

**Ограничение:** разные люди с одинаковым идентификатором объединятся. Без исходных адресов и общего реестра это не выявить. Если подготовкой занимаются несколько человек, им нужен общий актуальный реестр, передаваемый приватно. Проверка готовых ассетов и CI могут проверить формат, но уже не могут восстановить домены и выявить такие совпадения.

### 2. Проверить и создать PR

```sh
git switch -c attendance/2026-09-15
fvm dart run tool/attendance.dart validate
git add assets/attendance/2026-09-15-первая-встреча.txt
git diff --cached
git commit -m "Add attendance for 2026-09-15"
git push -u origin HEAD
gh pr create --fill
```

После успешных проверок слейте PR в `main`. Actions соберёт и опубликует новую версию. Обновите страницу после завершения workflow. Код и `pubspec.yaml` менять не нужно.

Можно сразу подготовить файл идентификаторов вручную, если почт нет. Перед коммитом всё равно запустите `validate`; проверка совпадений разных людей в этом случае остаётся ответственностью автора данных.

### 3. Исправить существующую встречу

Повторите команду `prepare` с той же датой и названием, новым исходным списком и флагом `--replace`, затем создайте PR с изменением **того же файла**. Без `--replace` утилита отказывается перезаписывать встречу. При исправлении даты или названия переименуйте исходный файл; не оставляйте старую копию, иначе она будет учтена как ещё одна встреча.

## Формат ассетов

- Каталог: `assets/attendance/`; один `.txt` на встречу, непосредственно в каталоге.
- Имя: `YYYY-MM-DD-название-встречи.txt`, реальная календарная дата. Название — строчные русские/латинские буквы и цифры, слова через дефис.
- Идентификатор: буквенный префикс имени (одна или несколько латинских букв), точка, фамилия латиницей; допустима составная фамилия через дефис. Например, `a.ivanov-petrov` или `an.ivanov`. Префикс сохраняется целиком: `a.ivanov` и `an.ivanov` — разные участники. Полные почты, пробелы внутри, цифры и комментарии запрещены.
- Пробелы по краям, регистр, пустые строки и дубли нормализуются при чтении.
- Пустой файл допустим: встреча учитывается в количестве встреч и последней дате, но не добавляет участников.
- Вложенные папки, ссылки и посторонние файлы запрещены; пустой `.gitkeep` сохраняет каталог до первой встречи.

Полные почты и реестр не должны попадать в репозиторий. Дополнительные правила `.gitignore` защищают от типичных CSV/TSV-экспортов, но не заменяют проверку `git diff --cached`. Примеры адресов в тестах синтетические; тесты не входят в веб-сборку.

## Проверки и сборка

С Flutter 3.47.4 в `PATH`:

```sh
bash tool/check.sh /InnoFormula-Enrolment/
```

Команда проверяет lockfile, форматирование, анализатор, файлы посещаемости, тесты и собирает release в `build/web/`. Тесты проверяют нормализацию, подсчёт и равные места, календарные даты, коллизии почт, CLI, настоящий AssetManifest, ошибки ассетов, состояния экрана и ширины 320/390/1440 px.

Проверка добавления нескольких новых ассетов без изменения конфигурации:

```sh
bash tool/smoke_assets.sh
```

Временные синтетические встречи удаляются после проверки. Для визуальной проверки готовой таблицы можно собрать отдельную локальную версию:

```sh
bash tool/smoke_assets.sh --preview
# Результат: build/fixture-preview/, base href: /.
```

## GitHub Pages

Workflow `.github/workflows/pages.yml` запускает проверки и release-сборку для каждого PR и каждого push в `main`. Только `main` загружается как Pages-артефакт и публикуется официальными `actions/configure-pages`, `actions/upload-pages-artifact`, `actions/deploy-pages`.

В **Settings → Pages → Build and deployment → Source** должен быть выбран **GitHub Actions**. Для копии проекта нужно включить этот режим один раз. Путь вычисляется по имени репозитория: `/InnoFormula-Enrolment/`; для репозитория `owner.github.io` используется `/`. При подключении собственного домена скорректируйте шаг `Compute Pages base path`.

За основу взят существующий [workflow Ars5njo/profile](https://github.com/Ars5njo/profile/blob/main/.github/workflows/deploy.yml). Здесь добавлены PR-проверки, фиксированный SDK, lockfile и отдельные права публикации.

## Структура

| Каталог | Назначение |
| --- | --- |
| `lib/data/` | AssetBundle / AssetManifest, парсер и подготовка почт |
| `lib/domain/` | Модели, интерфейс репозитория и чистая функция подсчёта |
| `lib/presentation/` | Тема и экран с StatefulWidget / FutureBuilder |
| `lib/main.dart` | Создание и передача зависимостей через конструкторы |
| `tool/` | Локальная подготовка и проверки |
| `test/` | Синтетические тестовые сценарии |

При ошибке любого файла приложение показывает ошибку всего рейтинга с повторной загрузкой. Шрифты Golos Text и Russo One включены локально с лицензиями SIL OFL в `assets/fonts/`. Логотип и адаптация Figma-референса описаны в [документации оформления](docs/branding.md).
